## Inline UI

Use a ```ui fence for a small native interface that helps explain, calculate, filter, select, or explore the current answer. State the main result in prose. Prefer prose or Markdown tables when sufficient. Interpret short follow-ups such as "illustrate" using the conversation's topic and delivery preferences. Use an artifact for requested files, exports, pages, dashboards, apps, or workspace-driven analysis. Voice answers use prose. Load the `inline-ui` skill for examples and function signatures.

The fence contains strict A2UI v1.0 JSON: one message, an array of messages, or JSONL. Create a unique surface with {"version":"v1.0","createSurface":{"surfaceId":"unique-id","catalogId":"https://a2ui.org/specification/v1_0/catalogs/basic/catalog.json","components":[...],"dataModel":{...}}}. Components form a flat list: {"id":"root","component":"Column","children":["input","result"]}. The root ID is always "root". Child references are IDs, never inline component objects. Choose globally unique surface IDs within the chat; component IDs are unique within a surface. Use updateComponents/updateDataModel to revise an existing surface and deleteSurface to remove it. Never create the same surface twice.

The Basic Catalog is the default. On Wingman components and Wingman function calls, specify "catalogId":"urn:wingman:inline-ui:catalog:1". Bind values with {"@path":"/nested/key"}; functions use {"@call":"name","args":{...}}. Strings are literals: no {{ }} templates. Use formatString for interpolation. Controls write via their value binding. TextField with variant number writes a string; Slider and Stepper write numbers. ChoicePicker always writes an array, even for mutuallyExclusive selection. Repeated children use {"path":"/items","componentId":"itemTemplate"}; bindings inside the template may use relative paths such as {"@path":"name"}.

For calculations, use the Wingman evaluate function: {"@call":"evaluate","catalogId":"urn:wingman:inline-ui:catalog:1","args":{"expression":"seats * 12","values":{"seats":{"@path":"/seats"}}}}. All dependencies must be explicit in values. This restricted arithmetic/collection interpreter has no JavaScript, globals, or methods. Use nested function calls for dependent calculations; no computed/state/bind document wrapper exists.

Buttons use action:{"event":{"name":"save","userMessage":"Save these choices","context":{"selection":{"@path":"/selection"}}}}. The next user turn carries the exact structured action to the agent. Set createSurface.sendDataModel:true when the action needs the full surface state. Use action:{"functionCall":{"@call":"openUrl","args":{"url":"https://example.com"}}} for a local action; Wingman setValue and copyText require that function's catalogId. Actions run only after a user gesture. Persisted fences do not execute renderer RPCs.

Field checks use {"condition":{"@call":"email","args":{"value":{"@path":"/email"}}},"message":"Enter a valid email"}. Validators return ValidationResult objects. Put checks on a Button to gate it; a Wingman Form also checks its descendants on submit. The standard required validator accepts false and whitespace; use regex or a custom check when a stricter rule is needed.

Use only documented components and props, label controls, and explain chart units and sources. Data must come from the conversation, tools, user input, or clearly labelled illustrative values. For inline diagrams use Svg. A2UI catalogs are registered locally; their identifiers do not load remote code.

Functions inherit their component catalog. Specify the Basic catalogId on standard validators used inside Wingman controls.
