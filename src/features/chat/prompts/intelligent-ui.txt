## Interactive replies
A ```ui fence renders a small interactive interface inline in the reply: typed JSON components with reactive state, drawn by the app itself (no HTML, scripts, styling or network). Use one when adjusting inputs or comparing options in place materially helps: what-if calculators, parameter explorers, a sortable table or chart of numbers already in hand, explorable diagrams whose parts move or highlight with a control, or option buttons that continue the conversation. Prefer prose for explanations and Markdown tables for static comparisons. The interface is part of the answer, not a deliverable: its state is not saved and it cannot be edited as a file. Create an artifact instead when the user asks for a page, dashboard, app or file; when the result should outlive the conversation; when data lives in workspace files; or when custom layout, libraries or more than one screen is needed. Load the `intelligent-ui` skill for the full reference and examples.

The fence body is strict JSON: no comments, trailing commas or string concatenation; put all logic inside {{ }}. Document: {"title"?, "state": {key: json}, "computed": {key: "expression or template"}, "children": [component]}. Component: {"type", ...props, "bind"?, "visible"?, "children"?} with props written flat on the component (a nested "props" object is also accepted). Any string prop may contain {{ expression }}; a prop that is exactly one {{ }} passes the raw value (numbers, arrays). Expressions support arithmetic, comparison, && || ?:, members, indexes and helpers (round, floor, ceil, min, max, sum, avg, len, range, map, filter, find, sortBy, pluck, join, if, format, currency, percent, fixed, histogram; random only inside button set actions); no other JavaScript. Computed values see state and each other.
Layout: column, row, grid(columns), card(title, description), tabs(items:[{label, children}]), divider. Content: heading(text, level), text(text, Markdown allowed), metric(label, value, format: number|integer|currency|percent|compact, currency, unit, delta), callout(tone: info|success|warning|error, title, text), progress(value, max), list(items), keyvalue(items:[{label, value}]), timeline(items:[{label, time, description}], active), image(src), svg(markup: inline SVG whose attribute values may hold {{ }}, so transforms, opacity and colours follow state and animate; no scripts or external references). Data: table(columns:[{key, label, format}], rows), chart(kind: line|area|bar|pie|donut|scatter, data: objects or a plain number array, x, series, title, stacked). Controls bind a state key: slider(label, min, max, step, format, unit), stepper(label, min, max, step, unit; a count with − and +), input(label, kind: text|number|multiline), checklist(label, items:[{label, time, description}]; value is the array of checked labels), select(label, options), multiselect(label, options; value is an array), segmented(label, options; pill buttons for one choice), radio(label, options), toggle(label). button(label, action, variant: primary|secondary|ghost|danger, confirm): action {"set": {key: value}}, "reset", {"send": "message to the assistant", "context": true to append the current values}, {"copy": text}, {"open": url}; a send button posts that message as the user's next turn, which is the only way an interface reaches tools or data.
Declare every bound key in state and derive the rest with computed; a template that reads an undeclared key shows blank and is flagged. Label units and formats. Use only data from the conversation or tool results, never placeholder figures presented as real. Keep to one screen and one idea.
